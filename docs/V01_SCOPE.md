# V0.1 第 0 步范围冻结

## 唯一验证目标

V0.1 只验证：用户能够从未来的远程入口委派一项本机 Codex 任务，系统持续记录状态，并根据真实证据报告完成、失败或等待用户。

本阶段只建立本地任务基础，不接入 Codex，不提供远程入口。

## 第 1 步包含

- 版本化的 Task、TaskEvent、Project、Device、Command 和 AuditLog 数据结构。
- 确定性的任务状态机。
- SQLite 本地持久化。
- 一个由本机明确授权的项目根目录，以及相对工作目录越界检查。
- 任务事件和审计日志。
- 以“来源设备 + 幂等键”为唯一约束的命令去重。
- 持久化取消请求和进程内 CancellationToken 信号。
- 启动时把未正常结束的任务标记为 Interrupted。

## 第 1 步明确不包含

- Codex、Claude 或其他 Agent 连接器。
- 手机端、云端、中继、推送和通知。
- 截图、桌面视频、远程键鼠和文件传输。
- 新的语音能力、唤醒词或实时通话。
- 通用 UI Automation 点击、发送、发布、删除、支付或账户操作。
- 长期记忆、向量数据库、计费和多用户协作。
- Jarvis 品牌重做；品牌清理将在单独批准后执行。

## 现有原型的复用边界

本阶段复用现有 `ScreenGuide.Core`、测试约定、严格编译规则和本地运行数据不入库规则。旧的 WPF、语音、截图、模型和 Windows 操作代码保持原样。

新任务层不得引用：

- `DesktopActionIntentParser`
- `SafeDesktopActionService`
- `SelectedWindowCaptureService`
- `MainWindow`
- 内存中的 `ConversationHistory` 或单布尔值授权

这些旧模块仍可运行，但不构成 V0.1 任务系统的信任边界。

## 数据与安全约束

- SQLite 文件必须由调用方放在当前用户的本地应用数据目录，不能写入仓库。
- 所有标识使用 GUID，所有时间使用 UTC。
- 用户文本和结构化载荷不能拼接成 SQL。
- 状态、任务事件和审计记录必须在同一数据库事务中提交。
- 任务只能使用已授权项目的相对工作目录。
- 恢复机制只标记事实，不擅自重新执行任务。
