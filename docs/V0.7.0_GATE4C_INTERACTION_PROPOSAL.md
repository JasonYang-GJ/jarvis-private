# Gate4C 交互修复与验收方案

日期：2026-09-12。状态：**PROPOSED / AWAITING_OWNER_DECISION**。这是具体待审方案，不是已实现功能或真实请求授权。

## 要修什么

现有 Client 先点击自身按钮和确认框，再读取前台窗口，导致读取目标变成元枢自身；第二次确认又与“原目标必须保持前台”的规则冲突。锚点、OCR 和人工阅读还共用 10 秒期限。诊断与当前候选身份见 [收尾检查](V0.7.0_CANDIDATE_CLOSEOUT.md)。

## 推荐交互

1. 用户在元枢输入问题，点击“询问指针位置”。第一次确认清楚说明本次只读目标窗口局部、图片不出站。
2. 确认后显示有时限的“等待选择目标”提示；用户主动切回要问的窗口，把指针放到目标文字，再按临时快捷键。快捷键只在这次可见准备期间注册，冲突则提示并停止，不常驻监听、不自动切换窗口、不移动鼠标。
3. 快捷键触发时，Host 才建立精确前台窗口与指针锚点。锚点到捕获/OCR 完成仍严格少于 10 秒；单窗口、最大 640×480、像素仅内存处理、取消立即清理等规则保持。
4. OCR 完成后在元枢展示完整冻结文字快照、问题、Provider/Model/HTTPS 去向、Prompt 身份，以及“不会发送图片”。用户可以正常阅读、拒绝或停止。
5. 用户确认这份快照后，界面提示主动回到同一个目标窗口并再次按临时快捷键。Host 重验原目标完整身份、位置/DPI、路由、Prompt、问题与 OCR 快照、Turn、预览 hash 和单次消费状态，再最多发送一次纯文本请求。目标不匹配则失效，绝不改抓新窗口或自动重新提问。
6. 新输入、新话题、停止、拒绝、关闭、重启、过期和路由/内容变更均撤销等待动作与快捷键。取消之后的迟到结果不得显示为成功。

## 需要 Owner 决定的合同变化

推荐把两个时限分开：**捕获锚点仍是 10 秒；已识别文字快照的阅读与单次发送确认最多 120 秒，自 OCR 完成时计时，不能续期。** 等待首次选择目标的可见准备期最多 30 秒。

这不是延长截图权限。10 秒过后不能再次捕获、再次 OCR 或复用原锚点读取新内容。120 秒仅允许用户决定是否发送已经显示并冻结的文字快照；必须明确说明这是刚才识别的文字，不能声称是发送时的实时内容。

该方案会改变当前 `PointerAnswerPreparedConsent` 与发送前目标验证的时限语义，所以不能当成普通文案修正。实施前需要确认上述行为，再进行窄范围架构/安全复核；本轮尚未修改这部分产品代码。若坚持当前全程 10 秒，可选用不抢前台的可见确认面板，但完整阅读长文本仍可能超时，不建议通过缩略预览来规避。

## 实施边界

- Client 仅持有一次性 UI 操作等待，不新增 Session/Turn 或“当前任务”状态真源；SessionCoordinator 仍是唯一协调入口。
- Host 区分“可以进行像素读取的锚点”与“可以确认发送的冻结文字快照”。不得给旧 RequireCurrent 增加宽泛绕过开关；读图路径仍执行原完整 10 秒校验。
- 不新增 Provider、不改 Prompt、不上传图片、不接长记忆、不扩大桌面动作白名单；不修改 schema，若确有 IPC 变更则先冻结对应版本合同。
- 新候选必须重新建立源码与产物身份，不沿用 `19081d3` 安装包的通过证据来证明修改后的 UI。
- 本批不安装覆盖正式用户数据、不签名、不发布、不进入手机或灵动岛开发。

## 验收清单

| 检查 | 必须得到的结果 |
| --- | --- |
| 外部目标 | 真实 Client 两次交互绑定同一专用测试窗口；不可用 IPC 代替真实按钮流程 |
| 首次拒绝、快捷键冲突、准备过期 | 无锚点捕获、无 OCR、无模型调用 |
| 捕获 10 秒边界 | 到期前允许、到期及之后拒绝，旧授权不能重新读图 |
| 冻结快照 | OCR 完成后不再读取像素；修改文字、问题、路由、Prompt 或目标使确认失效 |
| 阅读时限 | 120 秒内仅可消费一次；到期、取消、关闭、重启不可延长或复活 |
| 停止/替换与快速输入 | 旧等待、旧快捷键和旧请求被撤销，迟到结果不得覆盖新 Turn |
| 并发重复确认 | 最多 1 个 Provider 请求，禁止 retry/fallback/resend |
| 隐私 | 原始画面不落盘、不出站；真实 Key 不出现在日志、IPC、文档或测试文件 |
| 实机完整闭环 | 人工两次可见同意，真实局部 OCR、核对完整出站预览、一次纯文本请求、实际 Release Client 显示正确答案 |

## 最小真实验收内容

专用测试窗口只显示：`测试数值 2 加 3 等于多少`。问题固定为：`只根据这段测试文字回答计算结果。`

开始前先展示本轮实际候选 SHA、Prompt 文件与哈希、用户选择的 Provider/Model/官方 HTTPS 去向；Key 由用户通过可见设置提供。只使用隔离会话，不带历史、记忆或其他项目内容。

先完成零 Provider 的目标选择/OCR/预览，人工检查 OCR 实际文字与结构信息。之后展示最终冻结 payload，再取得一次真实请求及相应费用授权；最大 1 次模型请求，不额外运行 Health 检查，不切换路由、不重试。未获得该授权时停在预览，不能发送。

此时无法预先填入实际 OCR 尺寸/来源、最终 payload hash 或新的产品 SHA；不能伪造这些字段。它们是未来真实运行的前置结果，必须到时读取并冻结。
