## 八、安装验收脚本发现并修复的问题

旧脚本在已有正式安装的机器上用同一 AppId 临时安装再卸载，会移除正式版卸载登记，虽然不会删除正式程序目录和用户数据库。本轮发现后已完成：

- 给验收脚本增加保护：检测到正式安装目录或同 AppId 注册项时立即拒绝；
- 用哈希确认的原 V0.2.0 安装包在原目录执行同版本修复安装；
- 卸载登记恢复为 0.2.0；
- 再次验证 533/533 产品文件哈希一致；
- 再次验证 5/5 真实用户数据文件与原始快照一致。

以后安装/卸载验收必须在干净 Windows 测试机或虚拟机中运行。

## 十、仍然存在的风险

1. **同盘风险**：外部快照和 Git 仓库都在当前 C 盘；已可恢复误操作，但不能抵御整盘损坏。推送私有远端或复制到离线盘需要项目负责人另行授权。
2. **非逐字节可重复**：相同源码在不同绝对路径构建时，16 个元枢 PE 文件会因构建路径元数据产生不同哈希；Inno Setup 也包含构建时信息。功能、版本、文件集合和测试可重复，但不是 bit-for-bit 重现，因此正式候选哈希必须单独保存。
3. **无数字签名**：V0.2.0 和 V0.2.1 安装包均为 `NotSigned`，Windows 可能提示未知发布者。
4. **分发许可**：本机 Inno Setup 6.7.3 编译器显示 “Non-commercial use only”；语音模型许可证和分发方式也未完成商业核验。
5. **产品能力缺口**：统一会话中枢、真正长期记忆、Prompt 版本评测、第二个真实通用 Provider 尚未实现。
6. **多 Agent 环境限制**：本轮按 Git/代码/构建/文档/安全五条检查线执行，但当前环境没有可用 Orca CLI，无法启动真正独立的 Orca QA Worker；独立性由干净 Git 导出、隔离数据、第二轮全量测试和产物哈希复核实现。

这些风险均已明确记录，不会导致现有 V0.2 成果丢失，也不阻止阶段 0 通过；其中远端备份、代码签名和商业许可应在对外发布前解决。

## 十二、是否建议进入阶段 1

**建议进入阶段 1：统一会话中枢。**

理由：目前造成“理解不准、记忆不好、操作不连续”的首要问题不是缺少更大模型，而是语音、对话、动作、窗口和编程任务拥有不同状态入口。阶段 1 应只先统一 Session/Turn 和恢复边界，兼容现有数据与权限；不应同时扩展任意桌面操作、完整长期记忆或多模型路由。

本报告只给出建议，不会自动启动阶段 1，等待项目负责人确认。
