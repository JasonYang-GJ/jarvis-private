# 架构说明

## 建议技术路线

- 桌面应用：C# / .NET 10 LTS，Windows 原生界面。
- 画面授权：程序启动时请求仅对本次运行有效的前台窗口单帧授权；唤醒和问题识别时通过 Win32 取得当前前台窗口句柄，拒绝读取贾维斯自身，并用 `PrintWindow` 读取这一窗口的一帧。后续可替换为完整 Windows Graphics Capture 帧管线。
- 控件识别：Windows UI Automation，优先读取按钮、菜单和文字结构。
- 语音输入：Windows 中文识别与 sherpa-onnx 双通道共同完成本机唤醒，sherpa-onnx 在本机识别问题；麦克风音频不上传。
- 语音输出：百炼 CosyVoice 通过 WebSocket 接收 AI 文字片段并返回 PCM 音频；失败时可退回 Windows 中文声音。
- AI 分析：`IGuidanceProvider` 隔离模型供应商；普通问题默认使用百炼 `deepseek-v4-flash`，屏幕问题默认使用 `qwen3.7-plus`，两者均关闭思考模式并使用 SSE 流式输出。

## 组件边界

1. `WindowConsent`：已实现。启动时明确询问本次运行是否允许按需读取前台窗口；拒绝后普通问答仍可用，屏幕问题不截屏；程序退出后授权自动清除。
2. `BackgroundSession`：用户双击桌面图标后自动进入语音待命；管理设置窗口隐藏、系统托盘入口、开始和停止状态，不注册隐藏启动项。
3. `GlobalHotkey`：注册系统级语音和停止快捷键；常用组合冲突时依次选择备用组合。
4. `Speech`：三条本地通道持续等待唤醒词，唤醒后只识别一句问题；云端语音只接收 AI 生成的回答文字。长语音按缓冲区实际播放进度结束，不使用固定 15 秒截断。
5. `Overlay`：显示就绪、监听、识别和错误状态；使用不激活、鼠标穿透窗口，不抢走目标软件焦点。
6. `Capture`：只产生用户触发时当前前台窗口的一张内存画面，不负责联网；窗口句柄失效、属于贾维斯自身或无法定位时直接拒绝。
7. `UiInspection`：读取可访问控件树，不执行控件动作。
8. `Guidance`：组合画面、控件和用户问题，生成一步一条的指导。
9. `ModelProvider`：封装不同模型接口，应用核心不保存供应商密钥。
10. `LocalStorage`：API Key 使用 Windows 凭据管理器，非敏感配置位于 LocalAppData；截图只存在内存，不落盘。
11. `SafeDesktopAction`：只接受本地规则明确解析出的单条命令；当前白名单为打开抖音/Chrome，以及向当前窗口中可验证为“搜索”的输入框写入查询并确认。无法可靠定位控件时立即拒绝，不把普通 AI 回答当作操作命令。

## 数据流

用户配置百炼 → 双击桌面图标 → 确认或拒绝本次运行的单帧授权 → 自动进入后台待命 → 在任意软件中唤醒并提问 → 本机识别一句中文并记住当前前台窗口 → 普通问题不截屏并交给 DeepSeek；屏幕问题在已授权时抓取当前窗口一帧并交给千问视觉 → 百炼语音边合成边朗读 → 回答后继续待命，切换软件无需重新选择。

当前代码已接入单帧读取、百炼视觉模型和流式语音；屏幕画面会标记提问时的鼠标位置。Windows UI Automation 只用于受控搜索框定位和输入，尚未开放通用点击或任意控件操作。

## 开源边界

公开仓库只包含程序和示例。用户配置、模型密钥、真实画面、录音、操作记录和崩溃日志保存在仓库外，并默认不上传任何遥测。
